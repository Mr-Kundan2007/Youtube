# Payment Gateway Integration & Transaction Processing Guide

This guide details the payment infrastructure, Razorpay integration, order generation, cryptographic signature verification, test mode configuration, error handling, and refund procedures.

---

## 1. Payment Gateway Architecture

All monetary transactions are processed through **Razorpay Payment Gateway** supporting PCI-DSS Level 1 compliant card processing, UPI, Net Banking, and Wallets.

```
+------------------+         +------------------+         +--------------------+
|  Frontend Client |         | Platform Backend |         |  Razorpay Gateway  |
+------------------+         +------------------+         +--------------------+
         |                            |                              |
         | 1. POST /create-order      |                              |
         |--------------------------->| 2. razorpay.orders.create    |
         |                            |----------------------------->|
         |                            | 3. Order ID (order_xxx)      |
         |                            |<-----------------------------|
         | 4. Return order & options  |                              |
         |<---------------------------|                              |
         |                                                           |
         | 5. Open Razorpay Checkout overlay                         |
         |---------------------------------------------------------->|
         | 6. User authenticates UPI PIN / 3D-Secure OTP             |
         |<----------------------------------------------------------|
         | 7. Returns paymentId, orderId, signature                  |
         |                                                           |
         | 8. POST /verify-payment                                   |
         |--------------------------->|                              |
         |                            | 9. HMAC-SHA256 verification  |
         |                            |    Updates PaymentTransaction|
         |                            |    Activates Subscription    |
         |                            |    Generates Tax PDF Invoice |
         | 10. Activation Confirmed   |                              |
         |<---------------------------|                              |
         |                            |                              |
         |                            | 11. Async Webhook (fallback) |
         |                            |<-----------------------------|
```

## 2. Order Creation & Verification Flow

### Order Creation (`POST /api/subscriptions/create-order`)
* **Authoritative Pricing**: The backend strictly computes the price based on server-side constants. Client-provided prices are ignored to prevent tampering.
* **Currency**: All amounts are submitted to Razorpay in **paise** (1 INR = 100 paise).
* **Payment Record**: An initial `PaymentTransaction` record is created in MongoDB with status `created`.

### Cryptographic Signature Verification (`POST /api/subscriptions/verify-payment`)
* The signature generated by Razorpay is verified using standard HMAC SHA256:
  ```javascript
  const expectedSignature = crypto
    .createHmac("sha256", process.env.RAZORPAY_KEY_SECRET)
    .update(`${razorpay_order_id}|${razorpay_payment_id}`)
    .digest("hex");
  ```
* If signatures match, the transaction status is atomically updated to `success`.
* If signatures mismatch, the request returns HTTP 400 with `INVALID_SIGNATURE` and logs a fraud alert.

## 4. Webhook Processing & Idempotency

Razorpay sends asynchronous server-to-server HTTP POST notifications for critical events.

* **Webhook Endpoint**: `POST /api/subscriptions/webhook`
* **Signature Verification**: Validates the `X-Razorpay-Signature` header using `RAZORPAY_WEBHOOK_SECRET`.
* **Deduplication / Idempotency**:
  - Webhooks include an event ID in header `x-razorpay-event-id`.
  - The system checks `WebhookEvent` or `PaymentTransaction` before processing.
  - If already processed, returns HTTP 200 with `{ status: "already_processed" }` to prevent duplicate crediting.

### Handled Webhook Events:
1. `payment.captured`: Confirms payment capture; activates subscription if synchronous frontend verification was interrupted.
2. `payment.failed`: Marks transaction status as `failed` with error description; notifies user to retry.
3. `order.paid`: Confirms order fulfillment.
4. `refund.processed`: Records refund in transaction ledger and downgrades subscription if applicable.

## 5. Refunds & Chargeback Handling

* **Customer Refund Requests**: Handled by administrators via the Admin Dashboard or API (`POST /api/admin/subscriptions/refund`).
* **Refund Eligibility**: Within 48 hours of purchase if video downloads and streaming limits have not been extensively utilized.
* **Automated Audit**: Every refund issues an adjustment invoice and logs an `AdminSubscriptionAuditLog` entry.
